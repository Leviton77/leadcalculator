# Учёт лидов от рекламы OpenAI (ChatGPT) — отчёт по исследованию (issue #6)

_Дата: 2026-11-14. Только исследование, рабочий код не менялся._

## Коротко
У рекламной платформы OpenAI есть API и отчёты, но они отдают **агрегаты** (показы, клики, расход, конверсии) и принимают конверсии, которые присылает сам рекламодатель. **Данных о звонках по конкретному человеку платформа не отдаёт** (в доступной документации не найдено). Поэтому «взять звонки с платформы» не получится: надёжный учёт звонков даёт **отдельный номер телефона под эту рекламу**. Платформа OpenAI нужна как сверка (сколько кликов/конверсий и расход), а не как источник лидов.

**Рекомендация:** вариант B + C (отдельный номер + метки в ссылке), ручная сверка с отчётом OpenAI раз в период. Автоматический API — позже, если объём оправдает.

## 1. Что есть у платформы OpenAI (по открытым источникам)
- **Ads Manager**: показы, клики, расход, CTR, конверсии; выгрузка отчётов (по описаниям сторонних статей).
- **Advertiser API** (токен-авторизация): кампании, объявления, отчёты (Insights endpoints — агрегированные данные по аккаунту/кампании/группе/объявлению).
- **OpenAI Pixel + Conversions API**: сайт или сервер шлёт событие (например, «заявка»), OpenAI сопоставляет его с кликом по объявлению (идентификатор `oppref`, окно атрибуции клика, опционально 1 день просмотра).
- **Не найдено:** данные о звонках, список кликов с телефонами/именами. Доступ к API может быть ограничен (партнёрская настройка) — не подтверждено.

Источники: [developers.openai.com/ads](https://developers.openai.com/ads), [Conversion Measurement (Help Center)](https://help.openai.com/en/articles/20001409-conversion-measurement) (при проверке отдал 403, содержание взято из пересказа в поиске), [ads.openai.com/blog/more-ways-to-measure](https://ads.openai.com/blog/more-ways-to-measure), сторонние обзоры. **Нужно проверить на живом аккаунте Артёма**: есть ли доступ к API, какие метрики и разрезы доступны, видны ли конверсии типа «звонок/заявка».

## 2. Варианты

| Вариант | Как работает | Что ловит | Плюсы | Минусы | Трудоёмкость |
|---|---|---|---|---|---|
| **A. Метки в ссылках** (`utm_source=openai`) | Реклама ведёт на страницу с меткой; форма/письмо передаёт метку | Заявки с формы | Бесплатно, просто | Звонки напрямую не ловит; метка теряется, если человек позвонил | 0,5 дня (если есть контроль над формой) |
| **B. Отдельный номер (call tracking)** | Уникальный номер только в рекламе OpenAI (на странице и/или в объявлении); звонки на него = лид OpenAI | Звонки (надёжно) | Не зависит от клиента; источник однозначен | Платный номер/сервис (≈ несколько десятков CAD/мес), нужен учёт звонков | 1–2 дня |
| **C. Отдельная форма / страница** | Своя форма/URL только для OpenAI; письма формы идут с отдельной темой/адреса | Заявки | Надёжно, легко распознать в Gmail | Нужна вторая форма | 0,5–1 день |
| **D. Конверсии из API OpenAI** | Скрипт раз в период тянет отчёт Insights (клики, конверсии, расход) | Агрегаты для сверки | Подтверждает объём и расход | Не знает, кто именно; звонков нет; нужен доступ к API | 2–4 дня |
| **E. Спросить клиента** («как вы о нас узнали?») | Поле в форме / вопрос по телефону | Всё, но неточно | Дёшево | Субъективно, не гарантирует «ровно один источник» | 0,5 дня |

## 3. Как подключить к Leads Calculator

Текущее состояние: все лиды берутся из писем `leads@soumissionsdemenageurs.ca` (`src/Ingest.gs`), источник один и зашит в `src/Config.gs`.

**Настраиваемый список источников** — новая вкладка **Sources** в таблице:

| Источник | Платный | Правило распознавания | Приоритет |
|---|---|---|---|
| Soumission Déménageurs | да | письма от `leads@soumissionsdemenageurs.ca` | 10 |
| OpenAI | да | номер OpenAI в звонке / `utm_source=openai` / тема письма формы | 20 |
| Прочее/органика | нет | всё остальное | 99 |

**Правила, чтобы выполнялось «ровно один источник, без пересечений и потерь»:**
1. В **Leads Log** добавляется колонка «Источник». Заполняется при записи лида.
2. Источник определяется **по первому подходящему правилу в порядке приоритета**; если правил не сработало — «Прочее» (лид не теряется).
3. Один лид = одна строка = один источник; дедупликация по ключу (письмо/звонок), чтобы одно обращение не попало в два источника.
4. Платные источники считаются отдельно по периодам: для Soumission Déménageurs — как сейчас (по письму о продлении); для OpenAI — по календарным периодам (или по расходам из отчёта OpenAI). Колонка «Платный» управляет тем, попадает ли источник в блок стоимости.
5. Контроль: сумма лидов по всем источникам = общее число строк в логе (проверка в тестах и в итоговой строке периода).

**Приём лидов OpenAI (по выбранному варианту):**
- B (звонки): вести звонки на отдельном номере в журнал (call tracking сервис шлёт email/webhook → Gmail-метка `LeadsCalc/Source-OpenAI` или строка в лог); скрипт читает так же, как письма.
- A/C (формы): правило по теме/адресу письма формы или `utm_source`.
- D (API): отдельный необязательный модуль раз в период тянет Insights в вкладку «OpenAI Report» для сверки с числом лидов и расходом.

## 4. Трудоёмкость итогового внедрения
- Вкладка Sources + колонка «Источник» + правила + тесты: **1–2 дня**.
- Номер и/или форма (настройка у Артёма): **0,5–1 день**.
- Автоматическая сверка по API OpenAI: **+2–4 дня**, после проверки доступа.
